"""
Definition of the user ENROLL relationship dictionary.

For each learner, we construct a user-specific ENROLL relationship dictionary
to represent all course nodes under the learner-course enrollment relation.
This dictionary is designed as an intermediate structured representation,
so that subsequent learner variants can directly retrieve node-level and
relation-level information without repeatedly scanning raw JSON files or
embedding matrices.

Structure
---------
user_enroll_relation_dict = {
    "ENROLL": {
        "summary": {...},
        "nodes": {...}
    }
}

1. Relation-level information: "summary"
----------------------------------------
The "summary" field stores the overall information of the ENROLL relationship.

- relation_type:
    Fixed as "ENROLL", indicating that the current relationship is the
    learner-course enrollment relation.

- node_count:
    The total number of enrolled course nodes under the current ENROLL relation
    for the given learner.

- ignore_position:
    A boolean flag indicating whether the position effect should be ignored
    for all nodes in this relation.

    Rule:
    - ignore_position = True:
        (a) when there is only one node in the relation, or
        (b) when there are multiple nodes but all nodes have the same timestamp.
    - ignore_position = False:
        only when there are multiple nodes and their timestamps are not identical.

    If ignore_position = True, then:
    - all nodes are assigned position_time = 0
    - all nodes are assigned position_weight = 0.0
    - node_weight = first_weight_component

    If ignore_position = False, then:
    - position_time is computed according to timestamp grouping and ordering
    - position_weight is computed from position_time
    - node_weight = (first_weight_component + position_weight) / 2

- relation_weight_sum:
    The sum of node_weight over all nodes in the ENROLL relation.

- has_enroll_relationship:
    A boolean indicator showing whether the learner has any ENROLL relationship.
    It is True when node_count > 0, and False otherwise.

2. Node-level information: "nodes"
----------------------------------
The "nodes" field stores all enrolled course nodes under the ENROLL relation.
Each key is a course_id, and the corresponding value is a dictionary containing
the information of that course node.

For each course node, the following attributes are stored:

- course_id:
    The course identifier.

- enroll_time:
    The enrollment timestamp of the learner for this course.

- position_time:
    A discrete positional index derived from timestamp grouping and temporal ordering.
    It is not the raw timestamp itself, but an order-based position value.

- position_weight:
    The positional contribution of the node.
    When ignore_position = True, this value is set to 0.0 for all nodes.

- first_weight_component:
    The first component of the node weight, defined as the cosine similarity
    between:
        (1) the learner initial embedding, and
        (2) the initial embedding of the current course node.

- node_weight:
    The final weight assigned to the current node.
    Its computation depends on whether the position effect is ignored:

    - if ignore_position = True:
        node_weight = first_weight_component

    - if ignore_position = False:
        node_weight = (first_weight_component + position_weight) / 2

- course_final_embedding_index:
    The index of the current course in the final embedding matrix.
    The actual final embedding vector is not directly stored in the dictionary;
    instead, it is retrieved later from the .npy matrix using this index.

- course_initial_embedding_index:
    The index of the current course in the initial embedding matrix.
    This index is used for:
    - constructing the learner initial embedding, and
    - computing the first_weight_component of ENROLL nodes.

3. Design rationale
-------------------
This dictionary is designed to separate structured relationship information
from the embedding storage itself.

Instead of directly storing embedding vectors inside the dictionary,
we store only the corresponding matrix indices. This design:
- keeps the dictionary lightweight,
- avoids redundant storage of high-dimensional vectors,
- simplifies later matrix-based computation,
- and makes it easier to construct learner variants efficiently.

Therefore, the user ENROLL relationship dictionary serves as a reusable
intermediate representation between raw data processing and downstream
variant formulation.
"""

"""
用户 ENROLL relationship dictionary 的定义说明

对于每一个学习者（user），我们构造一个用户级别的 ENROLL 关系字典，
用于表示该学习者在“注册课程（ENROLL）”这一关系下的全部课程节点信息。
这个字典被设计为一种中间层的结构化表示，目的是为了方便后续 learner variants
的构造：后续在构造不同公式变体时，可以直接从该字典中提取节点级信息和关系级信息，
而不需要反复扫描原始 JSON 文件或 embedding 矩阵。

-----------------------------------
一、整体结构
-----------------------------------
user_enroll_relation_dict = {
    "ENROLL": {
        "summary": {...},
        "nodes": {...}
    }
}

其中：
- "ENROLL" 表示当前字典描述的是“用户注册课程”这一关系；
- "summary" 用于存储该关系整体层面的信息；
- "nodes" 用于存储该关系下每一个课程节点的具体信息。

-----------------------------------
二、关系层信息：summary
-----------------------------------
"summary" 用于存储当前用户在 ENROLL 关系下的整体统计信息，包括：

1. relation_type
   固定为 "ENROLL"，表示当前关系类型为用户注册课程关系。

2. node_count
   表示当前用户在 ENROLL 关系下所对应的课程节点总数。

3. ignore_position
   一个布尔值，用于表示当前关系下是否忽略所有节点的 position weight。

   判断规则如下：
   - 当关系下只有一个节点时，ignore_position = True；
   - 当关系下有多个节点，但这些节点的 timestamp 全都相同时，
     ignore_position = True；
   - 只有当关系下有多个节点，且这些节点的 timestamp 不全相同时，
     ignore_position = False。

   也就是说：
   只要当前关系下所有节点的 timestamp 完全相同，不管节点个数是 1 个还是多个，
   都认为 position 信息失效，因此忽略 position weight。

4. relation_weight_sum
   表示当前 ENROLL 关系下所有课程节点的 node_weight 之和。

5. has_enroll_relationship
   一个布尔值，用于表示当前用户是否具有 ENROLL 关系。
   - 当 node_count > 0 时，has_enroll_relationship = True；
   - 当 node_count = 0 时，has_enroll_relationship = False。

-----------------------------------
三、节点层信息：nodes
-----------------------------------
"nodes" 用于存储当前用户在 ENROLL 关系下的所有课程节点信息。
其键（key）为 course_id，值（value）为该课程节点对应的属性字典。

每一个课程节点包含以下字段：

1. course_id
   当前课程节点的课程 ID。

2. enroll_time
   用户注册该课程的时间。

3. position_time
   根据节点 timestamp 分组与排序后得到的位置编号。
   它不是原始 timestamp，而是基于时间先后关系得到的离散位置值。

4. position_weight
   当前节点的位置权重。
   当 ignore_position = True 时，所有节点的 position_weight 都统一设为 0.0。

5. first_weight_component
   当前节点权重中的第一部分，定义为：
   用户的 learner initial embedding 与该课程节点的 initial embedding
   之间的 cosine similarity。

6. node_weight
   当前课程节点的最终权重。

   其计算规则如下：
   - 当 ignore_position = True 时：
     node_weight = first_weight_component

   - 当 ignore_position = False 时：
     node_weight = (first_weight_component + position_weight) / 2

7. course_final_embedding_index
   当前课程在 final embedding 矩阵中的索引位置。
   字典中不直接存储课程的 final embedding 向量，
   后续需要时可通过该索引到 .npy 矩阵中查询。

8. course_initial_embedding_index
   当前课程在 initial embedding 矩阵中的索引位置。
   该索引用于：
   - 构造 learner initial embedding；
   - 计算当前 ENROLL 节点的 first_weight_component。

-----------------------------------
四、关于 ignore_position 的进一步说明
-----------------------------------
ignore_position 的核心含义是：
判断当前 ENROLL 关系下的位置因素是否有效。

如果当前关系下所有节点的 timestamp 相同，
则这些节点之间不存在有效的时间先后差异，
因此 position 信息不再具有区分作用，
此时将：
- 所有节点的 position_time 统一设为 0；
- 所有节点的 position_weight 统一设为 0.0；
- 所有节点的 node_weight 直接取 first_weight_component。

只有当当前关系下存在多个节点，
并且这些节点的 timestamp 不完全相同时，
position 信息才被认为有效，
此时才进一步计算各节点的 position_time 和 position_weight。

-----------------------------------
五、设计思想
-----------------------------------
该字典的设计目标，是将“结构化关系信息”和“高维 embedding 存储”进行分离。

因此，在字典中不直接存储 embedding 向量本身，
而只存储 embedding 在矩阵中的索引位置。
这样设计的优点包括：

1. 降低字典体积，避免高维向量的重复存储；
2. 保持数据结构清晰，便于调试与维护；
3. 方便后续直接结合 .npy 矩阵进行高效的矩阵运算；
4. 为 learner variants 的构造提供统一、稳定、可复用的中间表示形式。

因此，user_enroll_relation_dict 可以看作是：
从原始数据处理过程到下游 variant 公式构造之间的一个中间层表示。
"""
